Why the CRM would not load

The Supabase project hostname ixdnmjchvjzytyhmripc.supabase.co returns Non-existent domain. Supabase removes the subdomain when a project is paused, and free projects pause after about a week of inactivity. Every request the app makes resolves to nothing, so this is not a code or deploy problem, and clicking through from Vercel could never help.

A real bug made it look like a hang: getSession() had no .catch(), so a failed auth call left the gate stuck on LOADING forever with no message. That is fixed, and the same outage now explains itself on screen.

1. Open the Supabase dashboard
2. Click Restore project, wait for it to come up
3. Reload the CRM — data is retained while paused

Five-tab workspace

Event detail page
  • Plan · People · Comms · Media · Details
  • Counts render on the tabs, so you can see what an event still needs without opening each one
  • Tab choice persists for the session

Communications log

New
  • Who was contacted, on what channel, and where it stands
  • Sent · Awaiting · Replied · Confirmed · Declined, with an awaiting-reply count and filter
  • Naming a CRM contact also writes a touchpoint onto that contact, so the two histories cannot drift
  • Free-text recipients keep group blasts and outside vendors loggable

Media shelf

New
