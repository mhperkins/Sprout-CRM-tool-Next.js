What was built

One spec, three consumers

lib/eventPortal.js defines 9 sections and 64 fields. The client form, the CRM viewer, and the API's input filtering all render from it, so they cannot drift apart. Adding a field is one line.

Secret link per event

The token is the only credential and scopes every request to one booking. Rotatable from the CRM if a link gets forwarded somewhere it should not be.

Required vs. helpful

11 fields are the "cannot schedule without it" set and are called out at the top of the portal. The other 53 are planning detail and never block a booking.

New pending status

A request is not a calendar entry. Pending events never auto-complete, stay out of the newsletter, and show banana on the calendar until approved.

File uploads

Flyers, tech riders, insurance certificates, W9s. Uploads go straight from the browser, so a 20 MB artwork file does not hit Vercel's 4.5 MB request cap.

On the event page

Completion bar, what is still missing, the link with copy / open / rotate / remove, "Copy all answers" as plain text, and every answer grouped by section.

Verified against the live database, then cleaned up

✓
Request guards. Missing fields, honeypot, malformed email, and a per-email rate limit all reject correctly.
✓
Input filtering. Unknown keys, an out-of-enum value, a DROP TABLE string, a javascript: file URL, and junk inside a repeat row were all stripped.
✓
Event sync. Portal answers push name, date, times, and description onto the event, and never clear a field the portal left blank.
✓
Row-level security. As anon, both the portals table and the events table return 0 rows.
✓
Storage. Anon upload works, public read returns 200, anon delete is blocked.
✓
Layout. Screenshotted at 1000px and 390px. No horizontal overflow at either width.

One thing to know

Uploaded files sit at public URLs, the same as the newsletter images. A flyer or an insurance certificate is fine. Anything genuinely sensitive should not go through the upload fields. If that becomes a problem, the bucket can be switched to signed URLs later.

Where to point people

sprout-crm-tool-next-js.vercel.app/book is the public booking form. Put it on the website, in the link tree, and on the hosting QR code. For an event you already added by hand, open it in the CRM and hit Create portal link, then send that link to the organizer.
