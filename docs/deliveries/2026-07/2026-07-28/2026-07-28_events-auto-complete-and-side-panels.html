⏱ Past events auto-complete

Runs once on load · persists only what changed
  • One-time events flip upcoming → completed the day after their date. An event happening today stays Upcoming all day.
  • Recurring series stay Upcoming while they still have an occurrence today or later, and only complete once they run past their until date.
  • Cancelled events and events with no date are never touched.
  • A toast reports the count on load.

🔁 Per-occurrence completion

Derived, not stored

Occurrences aren't records. A recurring event is one row plus a rule, expanded at render time, so per-occurrence status is derived exactly the way the dates already are.

Past Fridays of a weekly series read completed while the series record stays upcoming and keeps recurring forever. Nothing accumulates in the database.

🗓 New event side panel

Same drawer idiom as contacts & orgs
  • People — first 3, then a show-more toggle; rows click through to that contact's panel
  • Next Actions — the checklist items, with overdue badges, one-click complete, and + Add Action
  • Event Details — date, time, location, repeat rule
  • Notes and Recap when present

🎯 Every action row opens in place

One handler for all three types

Contact, org, and event actions now behave identically. Org actions render the existing org panel rather than navigating to the Orgs page, and the Upcoming Events card opens the event panel too.

Open in Events → deep-links to that specific event's page, reusing the handoff pattern contacts already had.

🌍 The timezone trap this had to dodge

Why a new local-date helper exists

The app computes "today" as new Date().toISOString().slice(0,10), which is UTC and rolls over around 8pm Eastern. A naive comparison would have marked an evening event Completed while it was still running, and this one writes to the database rather than just affecting display.

The auto-complete uses a new localTodayISO() instead. The rest of the app keeps its existing UTC date on purpose, since changing seven call sites is a wider blast radius than the ask. The local boundary is always later than the UTC one, so the auto-complete is strictly more conservative and the two can never disagree in a way that produces a wrong write.

🐛 Latent crash found and fixed

OrgDetail.moveSegment

The org panel's "Move to" button called setSegMenuOpen, a state setter that only exists in the contact panel. It would have thrown a ReferenceError on any click. Leftover from when the org panel was copied from the contact one, and surfacing that panel on the dashboard made it easy to reach. Removed the stray call.
